# Полировка хранилища open_777 (Liber 777) — дизайн

Дата: 2026-06-26

## Контекст
Хранилище `obsidian_777_vault` генерируется `_scripts/generate_vault.py` из
`docs/liber_777.csv` (40 колонок) + JS-источник, затем обогащается скриптами
(78 Дверей, Боннер, разбивка дворов) и вручную (07 Numbers, ядра/квинтэссенции, Даат).
**Хранилище разошлось с чистой генерацией** — `reset_managed_dirs()` (rmtree папок 01–06)
сделал бы regen разрушительным. Источник полнее — `Downloads/...DataComplete.csv` (102 кол.).

Сущности (06 Entities, 689 шт.): deity, demon, angel, spirit, animal, plant, stone,
perfume, color, magical_weapon, other. Плюс tarot (03), hebrew letters (04),
astrology (05), numbers (07).

## Проблема
1. Свойство `correspondences` — **вложенный словарь** в frontmatter. Obsidian не умеет
   вложенные объекты в свойствах → рендерит JSON-блобом, ссылки не кликабельны.
   (Плоский `corresponds_to` со всеми ссылками уже работает как «общее облако».)
2. Полнота: ~60 шкал соответствий из DataComplete не сгенерированы.
3. Возможные дыры в целостности (битые/односторонние ссылки, сироты) — проверить.

## Цель
Вошёл в сущность → видишь **типизированные кликабельные облака** соответствий
(растения, карты, боги, буквы…), связи протянуты «от всего ко всему» и двунаправленно,
данные полные.

## Архитектура (зафиксировано)
**In-place аддитивные миграции.** Скрипты меняют только frontmatter и создают
недостающие заметки; тело и ручные блоки (BONNER_*, 78_DOORS, RAW_CORE, QUINTESSENCE,
PATH_IMPORT и пр.) не трогаются. Разрушительный regen НЕ запускаем; `generate_vault.py` —
референс (синхронизация генератора — опциональный follow-up). Перед каждым этапом —
бэкап (git-снапшот vault + копия папки). Миграции идемпотентны.

Последовательность: **I → II → III**.

---

## Под-проект I — типизированные кликабельные облака  (ДЕТАЛЬНО)

Скрипт `_scripts/fix_correspondences.py` (in-place, идемпотентный).

Для каждой заметки `01 Sefirot/*` и `02 Paths/*`:
1. Собрать связанные сущности из `corresponds_to` + сломанного `correspondences.*` + ссылок
   в таблице «Все соответствия» (объединить, дедуп).
2. Сгруппировать по ТИПУ цели: тип сущности берётся из `entity_type` заметки-цели
   (deity/demon/angel/spirit/animal/plant/stone/perfume/color/magical_weapon/other);
   карты → tarot, буквы → letter, знаки/планеты → astrology, числа → number.
3. Записать плоские свойства-списки (multitext, кликабельные):
   `corr_deities, corr_demons, corr_angels, corr_spirits, corr_animals, corr_plants,
   corr_stones, corr_perfumes, corr_colors, corr_weapons, corr_other, corr_tarot,
   corr_letters, corr_astrology, corr_numbers`. Пустые типы не добавляем.
4. Удалить сломанный вложенный `correspondences`. `corresponds_to` оставить как «всё облако».
5. Тело заметки (таблицы, ручные блоки) не трогать.

Прочее:
- Зарегистрировать все `corr_*` как `multitext` в `.obsidian/types.json`.
- Опционально продублировать схему в сущностях (обратные типизированные облака) — решим в II.

Проверка: Yesod показывает кликабельные чипы по типам; ни одного JSON-блоба
`correspondences` в vault; число ссылок в типизированных свойствах = числу в `corresponds_to`.

## Под-проект II — целостность связей  (ОБЗОРНО)

Скрипт-аудит `_scripts/audit_links.py` (только отчёт, без правок) + точечный ремонт.
Проверяем:
- **Битые вики-ссылки:** цель `[[X]]` без файла X.
- **Двунаправленность:** если сфира/путь ссылается на сущность — у сущности есть
  `appears_in`/обратная ссылка, и наоборот.
- **Сироты:** заметки без входящих/исходящих связей.
- **Дубли имён** (алиасы/нормализация — ср. `entity_aliases.py`).
Ремонт — отдельным идемпотентным скриптом по утверждённому отчёту.

## Под-проект III — полнота из DataComplete  (ОБЗОРНО, свой спец позже)

- Сопоставить 102 колонки DataComplete → типы сущностей и шкалы (схема-маппинг).
- Аддитивно: создать недостающие заметки-сущности, дописать недостающие ссылки в
  типизированные `corr_*` сфир/путей + обратные ссылки. Существующее не перетирать.
- Дедуп против уже существующих сущностей (нормализация имён).
- Своя спека с таблицей маппинга колонок до реализации.

## Риски и откат
- Перед каждым этапом: `git add -A && git commit` в vault + копия папки `_backup_<ts>`.
- Все миграции идемпотентны (повторный прогон не плодит дублей).
- Ничего не пушим/не удаляем без явного слова.
